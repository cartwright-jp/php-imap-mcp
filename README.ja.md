# php-imap-mcp

[English](README.md) | 日本語

独自ドメインのメールを、Claude から IMAP で読み・検索し・下書き保存できるようにする、PHP 製のリモート [MCP](https://modelcontextprotocol.io/) サーバーです。共用のレンタルサーバーに置くだけで動きます。常駐プロセスも、追加のサーバーも、データベースも要りません。

この文書は [README.md](README.md)（英語）の翻訳です。内容が食い違うときは英語版が優先します。

- **読む・下書きするだけで、送らない。** AI ができるのは、フォルダの一覧、検索、メールを読むこと、下書きの保存です。送信と削除はできません。下書きは人が確認して、手元のメールソフトから送ります。
- **メールアカウントでログインする。** サーバーのログイン画面で、メールアドレスとパスワードを入力します（OAuth）。メールのパスワードはサーバーに保存しません。
- **共用サーバー向けの作り。** 1回のリクエストごとに IMAP へ接続して切断し、セッションの状態を持ちません。Apache と `.htaccess`、PHP 8.1 以上で動き、ext-imap は使いません。
- **日本語のメールに対応。** ISO-2022-JP、Shift_JIS、HTML だけのメール、日本語のフォルダ名を正しく扱います。

> [!WARNING]
> このソフトウェアは、AI にメールボックス全体を読む権限を与えます。また、メールの内容には、メールを送ってきた誰もが指示を書き込めます（プロンプトインジェクション）。メールボックスをつなぐ前に [セキュリティ](#セキュリティ) を読み、AI 専用のメールボックスを使うことを検討してください。

## ツール

| ツール | 内容 |
| --- | --- |
| `list_folders` | フォルダの一覧。特殊用途（受信、送信済み、下書きなど）、総数、未読数つき |
| `search_emails` | 1つのフォルダを、差出人、宛先、件名、本文、日付、未読で検索する。新しい順で、本文の冒頭つき |
| `get_email` | 1通のメール。ヘッダー、テキストにした本文（HTML は変換）、添付ファイルの名前と大きさ（中身は返さない）。指定しない限り既読にしない |
| `save_draft` | テキストの下書きを下書きフォルダに保存する。返信では `In-Reply-To` と `References` を付け、スレッドにつながるようにする。`quote: "full"` で、本文の下に元のメールを引用する |

ツールは設定で1つずつ無効にでき、`policy.allowed_folders` で読めるフォルダを絞れます。

設計上、対応しないもの: メールの送信、削除、新着メールの通知（IMAP IDLE には常駐プロセスが要るため）、IMAP 以外のプロトコル。

## しくみ

```
Claude（Web、デスクトップ、スマホ）
   │  HTTPS、Anthropic のクラウドから
   ▼
独自ドメイン/mcp/   ── PHP、1リクエストずつ ──▶  IMAP サーバー（TLS）
```

1. claude.ai にカスタムコネクタとして登録すると、Claude がサーバーのログイン画面を開きます。
2. メールアドレスとパスワードでログインします。サーバーは実際に IMAP でログインして確かめます。
3. サーバーは、メールアドレスとパスワードを、サーバーだけが持つ鍵で暗号化して（封をして）、アクセストークンとして発行します。パスワードの保存庫は持ちません。
4. 以後のリクエストごとに、サーバーはトークンを開いて IMAP に接続し、処理をして切断します。

## 動作環境

- PHP 8.1 以上と、`iconv`、`json`、`mbstring`、`openssl`、`sodium` の拡張
- `.htaccess` と `mod_rewrite` が使える Apache。HTTPS で公開すること
- TLS で接続できる IMAP サーバー（993番ポート、または STARTTLS）
- 導入に使う SSH と Composer

国内の共用レンタルサーバー（Apache、Courier-IMAP）と、claude.ai の Web 版・スマホのアプリで動作を確かめています。自動テストは PHP 8.1〜8.4 で、Courier-IMAP と Dovecot を相手に実行しています。

## 導入

詳しい手順は [配置の手順書](docs/deploy-xserver.md) にあります。以下はその要点で、似たサーバーでも使えます。`example.com`、`imap.example.com`、パスは自分の環境に読み替えてください。

1. **公開ディレクトリの外に置く。**

   ```sh
   git clone https://github.com/cartwright-jp/php-imap-mcp.git ~/php-imap-mcp
   cd ~/php-imap-mcp
   composer install --no-dev --optimize-autoloader
   ```

2. **設定を書く。** 見本をコピーして自分だけが読めるようにし、鍵とシークレットを作ります。

   ```sh
   cp config.example.php config.php && chmod 600 config.php
   php bin/generate-key.php            # → auth.oauth.key
   php bin/generate-client-secret.php  # ハッシュを auth.oauth.clients[].secret_hash に。シークレットは claude.ai に入力するので控えておく
   ```

   `config.php` では、少なくとも `auth.oauth.resource`（MCP の URL。例: `https://example.com/mcp/`）、`auth.oauth.imap.host`（例: `imap.example.com`）、`auth.oauth.allowed_email_domains` を書き換えます。知らないキーや安全でない値は拒否されるので、綴りの誤りで制限が黙って外れることはありません。

3. **設定と IMAP のログインを確かめる**（パスワードを尋ねられます。保存はしません）。

   ```sh
   php bin/check-config.php --login you@example.com
   ```

4. **入口を公開する。** `public/index.php` と `public/.htaccess` を公開ディレクトリ（例: `public_html/mcp/`）にコピーし、その `index.php` の `APP_ROOT` を、手順 1 で置いた場所に書き換えます。公開するのはこの2つのファイルだけです。

5. **サイト直下から OAuth のメタデータを見えるようにする。** [手順書の5章](docs/deploy-xserver.md#5-サイト直下からメタデータを見えるようにする) の転送の設定を、サイト直下の `.htaccess` の先頭に足します。

6. **claude.ai からつなぐ。** 「設定」→「コネクタ」→「カスタムコネクタを追加」で、MCP の URL を入力します。「詳細設定」に、OAuth のクライアント ID（見本では `claude`）と、手順 2 で控えたクライアントシークレットを入力します。「接続」を押すとログイン画面が開くので、ログインします。

MCP のエンドポイントは、`auth.allowed_ips` の IP からの要求だけを受け付けます。初期値は [Anthropic の送信元の IP 範囲](https://platform.claude.com/docs/en/api/ip-addresses) です。Claude Code のように自分の PC から直接つなぐクライアントを使う場合は、自分の IP も足してください。ログイン画面はブラウザで開くので、IP 制限の対象外です。

更新するときは、新しい版を取得して `composer install --no-dev --optimize-autoloader` をやり直します。`public/` の2つのファイルが変わったときは、コピーし直して `APP_ROOT` を書き直します。`config.php` と `var/` はそのまま残ります。

## セキュリティ

実際のメールボックスをつなぐ前に読んでください。脆弱性の報告は [SECURITY.ja.md](SECURITY.ja.md) を見てください。

**AI 専用のメールボックスを使う。** AI は、ログインしたメールボックスの中をすべて読めます。別のアカウントを作り、AI に扱わせたいメールだけを転送してください。

**プロンプトインジェクション。** メールを送れる人なら誰でも、メールの中に指示を書けます。サーバーはメールの内容を信頼できないデータとして区切り、AI に従わないよう伝えますが、AI が必ず無視するとは保証できません。被害を小さくするしくみは次のとおりです。

- サーバーはメールを送信も削除もできません。悪意のあるメールが、このサーバーを使ってあなたのメールをどこかへ転送させることはできません。
- 下書きは下書きにすぎません。送る前に、必ず宛先と内容を確かめてください。
- 同じ会話にある別のコネクタは、このサーバーでは制限できません。そこで Claude がメッセージの送信や外部への書き込みもできるなら、埋め込まれた指示がそちらを使うおそれがあります。

**サーバーが守っているもの。**

- メールのパスワードはサーバーに保存しません。サーバーの鍵でトークンに封をしています（libsodium）。パスワードを取り出すには、鍵とトークンの両方が必要です。
- ログイン画面では、設定したドメインのメールアドレスだけがログインできます。ログインに続けて失敗すると、その IP アドレスとメールアドレスをしばらく締め出します。
- MCP のエンドポイントは、許可した IP 範囲からの要求だけを受け付け、`Origin` ヘッダーも確かめます。IMAP は必ず TLS で接続し、証明書を検証します。
- 監査ログには、ツールの呼び出しごとに、時刻、アカウント、ツール、引数の要約、結果、所要時間を記録します。パスワード、トークン、メールの本文は記録しません。下書きは、宛先、件名、本文の文字数（引用したときは、引用の方法と文字数）だけを記録します。
- ログインは `php bin/revoke-grant.php <grant>` で1件ずつ取り消せます。鍵を入れ替えれば、全員をまとめてログアウトさせられます。

## 開発の状況

v0.2 です。作者が共用レンタルサーバーで毎日使っています。v0.2 で、返信の下書きに元のメールを引用できるようになりました。次（v0.3）は、既読・フラグの操作、メールの移動（どちらも初期は無効）、依存を同梱した zip の配布、ブラウザで設定できる画面を予定しています。[CHANGELOG.md](CHANGELOG.md)（英語）も見てください。

既知の制限:

- 下書きの `From` はメールアドレスだけで、表示名が付きません。メールソフトによっては（例: Outlook）、この `From` のまま送ります。
- 今のところ、確かめたのは1つのレンタルサーバーだけです。ほかのサーバーでの報告を歓迎します。
